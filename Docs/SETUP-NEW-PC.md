# Opening BAM on a new PC (e.g. Simon's)

The repo is the source code and every small asset. Some big or build-only files live only on Rickard's PC
(`C:\Users\Rickard\BattleArenaMasters`) and some Unity files are generated by our own menus. His PC is kept at the latest
`main` by copying each checked commit to it (it ran main `a8fc5ec` on 2026-11-18, when this list was made).

## Steps

1. Clone `rickardlundgren91/Battle-Arena-Masters` and open the folder with **Unity 6000.6.5f1** (Unity 6.6, URP).
2. **Hero models V2 (not in git, about 900 MB):** copy Rickard's folder `Assets\BAM\Art\ModelsV2\` (with every `.meta` file)
   to the same place in your project. The heroes' current bodies and all skins are in it.
   It is too big for plain git (the skin FBX files are up to 36 MB each); get it as a zip from Rickard.
3. **BAM > Setup Project** (out of Play): builds `Assets/BAM/Scenes/Main.unity`, the URP quality assets and the build
   settings. Never commit the scene or the generated URP assets; every PC makes its own.
4. **BAM > Art > Create Materials**, then **BAM > Art > Rebuild Hero Models** (out of Play): makes the `BAM_*.mat` files and
   `Resources/BAMArt/Heroes|Minions/*.asset` from the models. Run Rebuild again after a pull that changes
   `Art/Editor/HeroArtImport.cs` or anything in `ModelsV2`.
5. Press Play. Play always starts from `Main.unity`.

## Only on Rickard's build PC (not needed to work in the editor)

- Google Play Games plugin (`Assets/GooglePlayGames`, `Assets/ExternalDependencyManager`), `Assets/Plugins/Android`
  (gradle templates) and the Google Play packages (`Packages/*.tgz`: appbundle, appupdate, review, core, common, EDM).
  The code builds without them: in-app update and review ask are switched off by `versionDefines` in `BAM.UI.asmdef`.
- The `BAM_ONLINE` define for Android (Player Settings). Leave it unset unless you install the Play Games plugin, or
  `BAM.Online.PlayGames` will not compile. Without it the editor plays offline (bots, tutorial, hero test).
- Signing keystore and its passwords: never in git, never in chat.
- Building and uploading to Google Play is Rickard's job.

## Working together

- Claude pushes small checked commits to `main` often (several an hour on busy days). **Pull before you start and before
  you commit.** Work on your own branch and open a pull request, or tell Rickard before pushing to `main`.
- Do not commit `ProjectSettings/`, `Packages/manifest.json` or `packages-lock.json` from your PC without asking: the
  build PC's versions differ on purpose (see above). Never commit `GvhProjectSettings.xml`, keystores or `google-services.json`
  (`.gitignore` blocks them).
- Big new binaries (FBX over a few MB) go in `ModelsV2` and are handed over outside git, as above.
- Everything else, the rules of the game and how the code is laid out: `README.md`, `CLAUDE.md`, `Docs/ARCHITECTURE.md`.
